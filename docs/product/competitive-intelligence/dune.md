## 3. Information Architecture

Navigation is dashboard, query, creator, and dataset oriented. Hierarchy depends on each dashboard author. Grouping is flexible but inconsistent. Progressive disclosure can be excellent when authored well and poor when not. Density varies. Search helps discovery. Filtering depends on dashboard design. Workspace is builder-oriented.

## 4. Visualization

Charts and tables are central. Cards summarize dashboard metrics. Heatmaps/timelines depend on author design. Network graphs are possible but not core. Animations are minimal. Typography and spacing vary by dashboard. Color language is creator-dependent.

## 5. Decision Support

Users reach conclusions through analyst-built dashboards and transparent queries. Evidence is query-backed when the query is visible. Reasoning depends on authors. Historical context can be strong. Confidence is not standardized. Counter-evidence requires query review or alternate dashboards.

## 6. UX

Learning curve is low for consumption and high for creation. Onboarding is split between dashboard users and query builders. Interaction is search, query, chart, filter, fork, and dashboard driven. Customization is excellent. Desktop is primary. Mobile is secondary. Accessibility varies by dashboard.

## 7. Strengths

- Query transparency.
- Community dashboard creation.
- High flexibility.
- Strong data storytelling potential.
- Composable analytics.

## 8. Weaknesses

- Quality varies by author.
- Dashboards may lack consistent UX.
- Query literacy barrier.
- Trust requires review.
