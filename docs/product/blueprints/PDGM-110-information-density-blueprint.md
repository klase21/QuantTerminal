## 1. Purpose

Information Density defines how QuantTerminal expands from fast understanding to professional depth.

Primary user question: How much information should I see right now?

Expected user outcome: The user can choose the right depth without being forced into unnecessary complexity.

## 2. Inputs

| Input | Role |
| --- | --- |
| Repository | Deepest raw fact layer. |
| Evidence | Primary mid-density trust layer. |
| Reasoning | Future higher-level interpretation layer. |
| Research | Deep narrative and source context. |
| Replay | Historical event depth. |
| Signals | Scanner and Trade candidate density input. |
| Historical Context | Analog and replay context. |
| Macro | Optional evidence category. |
| Prediction Markets | Optional evidence category. |
| User Preferences | Density mode, saved views, accessibility, and professional workflow preference. |

## 3. Outputs

The user can decide whether to stay at a headline level, inspect evidence, open charts, replay history, enter research, or inspect raw repository data.

The user gains control over complexity.

## 4. Information Hierarchy

Level 1: Beginner  
Headline, main evidence, and clear unavailable states.

Level 2: Intermediate  
Evidence Cards, simple charts, and short reasoning summaries.

Level 3: Professional  
Dense charts, filters, cross-market evidence, and replay context.

Level 4: Research  
Narrative, counter-evidence, source comparison, and historical context.

Level 5: Repository  
Raw facts, record lineage, provider metadata, and source timestamps.

## 5. User Journey

Entry: User lands on a screen at the default density level.

Primary workflow: Scan, expand, drill down, compare, and decide whether deeper investigation is needed.

Secondary workflow: Switch density, save density preference, open professional mode, or inspect raw facts.

Exit: User keeps the current density or returns to a simpler view.

Context preservation: Density changes should preserve symbol, time window, evidence, and selected workflow.

## 6. Interaction Model

Click: Expand depth, switch density, open charts, or inspect repository.

Hover: Reveal concise metadata without adding visual clutter.

Expand: Move from summary to evidence to charts to raw details.

Drill-down: Each density level can open the next deeper level.

Cross-navigation: Density preference follows context where appropriate.

Search: Respect the user current density but allow advanced results.

Filtering: Increase specificity without hiding critical evidence.

Workspace: Saved layouts may preserve density.

Saved Views: Store preferred density and context.

## 7. Dependencies

Information Density depends on MASTER_PRODUCT, Design DNA, Information Architecture, Pattern Library, and Accessibility rules.

It constrains every screen blueprint.

## 8. Success Criteria

- Users understand the first screen quickly.
- Professional users can reach depth without friction.
- Beginners are not overwhelmed.
- Raw repository data is available without becoming the default.
- Density changes do not break context.

## 9. DO

- Always start with the clearest useful layer.
- Always allow deeper inspection.
- Always keep warnings and unavailable states visible.
- Always preserve context across density changes.
- Always support accessibility at every density level.

## 10. DO NOT

- Do not show every data layer at once.
- Do not make raw records the default product experience.
- Do not hide critical evidence in advanced mode only.
- Do not duplicate the same content to simulate depth.
- Do not use density as decoration.

## 11. Future Expansion

Information Density may evolve toward personalized density profiles, enterprise analyst modes, mobile density presets, adaptive layouts, and AI-assisted summarization.

Future expansion must preserve user control and evidence visibility.
