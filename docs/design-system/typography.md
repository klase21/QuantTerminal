# Typography

**Owner:** Product Design  
**Status:** Canonical

## Purpose

Typography creates scan order, supports dense analysis, and distinguishes
facts, interpretation, metadata, and machine-readable values.

## Roles

| Role | Use |
| --- | --- |
| Display | Rare product-level statement or major empty-state orientation |
| Heading | Screen and major section hierarchy |
| Title | Panel, card, chart, or object identity |
| Subtitle | Supporting context beneath a title |
| Body | Explanations, summaries, and readable prose |
| Caption | Source, freshness, timestamp, limitation, and secondary metadata |
| Label | Controls, fields, status names, axes, and compact object descriptors |
| Code | Identifiers, queries, record references, and technical literals |
| Numeric | Prices, percentages, counts, timestamps, and comparative metrics |

## Hierarchy Rules

- One dominant heading per primary view.
- Card typography remains compact; hero scale is reserved for true orientation.
- Numeric typography prioritizes stable alignment and comparison.
- Metadata is subordinate but never illegible.
- Status labels remain readable without color.
- Long-form Research uses comfortable body rhythm; operational surfaces use
  tighter but accessible rhythm.

## Content Rules

- Use sentence case for prose and commands.
- Use canonical uppercase only for defined machine states such as `UNAVAILABLE`.
- Avoid decorative capitalization and compressed letter spacing.
- Preserve exact symbols, dataset names, IDs, and timestamps.
- Do not use typography to make unsupported claims appear authoritative.
