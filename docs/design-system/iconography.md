# Iconography

**Owner:** Product Design  
**Status:** Canonical

## Philosophy

Icons accelerate recognition in repeated workflows. Familiar symbols may stand
alone when their meaning is established; unfamiliar, domain-specific, or
consequential icons require labels or tooltips.

## Rules

- Use one coherent icon family and consistent optical treatment.
- Prefer icons for familiar tools and icon-plus-text for clear commands.
- Do not draw bespoke icons when the approved library contains an equivalent.
- Direction, risk, status, and availability must not rely on icon shape alone.
- Icons remain stable across screens for the same concept.

## Semantic Categories

| Category | Concepts |
| --- | --- |
| Evidence | source, provenance, verified, experimental, unavailable |
| Research | document, source, thesis, counter-evidence, citation |
| Replay | timeline, play, pause, step, event, history |
| Risk | warning, invalidation, exposure, destructive action |
| Navigation | home, back, forward, breadcrumb, external context |
| Workspace | pin, save view, layout, synchronize, detach |
| Alerts | notification, priority, acknowledgment, muted |
| Macro | rates, currency, volatility, calendar context |
| ETF | flow, allocation, issuer, basket |
| Prediction Markets | probability, market, resolution, uncertainty |

## Interaction

Interactive icons expose accessible names, visible focus, and disabled state.
Icon-only controls maintain stable hit areas and provide tooltips for meanings
that are not universal.
