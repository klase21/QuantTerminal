# QuantTerminal Automation Task Schema

Status: schema foundation  
Scope: Planner Agent task JSON  
Runtime behavior: none

## Purpose

The Planner Agent emits a structured task object that downstream agents can execute, validate, and review without inferring scope from prose alone.

## Minimal Task Shape

```json
{
  "goal": "",
  "scope": [],
  "constraints": [],
  "validation": [],
  "expected_output": []
}
```

## Canonical Task Schema

```json
{
  "schemaVersion": 1,
  "taskId": "",
  "title": "",
  "goal": "",
  "mode": "documentation | implementation | review | certification",
  "scope": [
    {
      "path": "",
      "allowedChanges": []
    }
  ],
  "constraints": [],
  "forbiddenChanges": [],
  "requiredReading": [],
  "validation": [
    {
      "command": "",
      "required": true
    }
  ],
  "expected_output": [],
  "acceptanceCriteria": [],
  "reviewCriteria": [],
  "screenshotTargets": [],
  "approvalRequired": false
}
```

## Field Definitions

### `schemaVersion`

Task schema version. Starts at `1`.

### `taskId`

Stable task identifier generated by Planner Agent.

### `title`

Short human-readable sprint or task title.

### `goal`

The concrete outcome the task must achieve.

### `mode`

One of:

- `documentation`
- `implementation`
- `review`
- `certification`

### `scope`

Files or directories the Codex Worker may touch.

### `constraints`

Rules that must remain true during the task.

### `forbiddenChanges`

Explicitly prohibited changes.

### `requiredReading`

Documents or files agents must read before acting.

### `validation`

Commands or checks that must run before review.

### `expected_output`

Final response requirements.

### `acceptanceCriteria`

Conditions required to mark the task complete.

### `reviewCriteria`

Review Agent checklist.

### `screenshotTargets`

Viewport and route targets for Screenshot Agent.

### `approvalRequired`

Whether Telegram Approval Agent must collect explicit human approval before the workflow can proceed.

## Example

```json
{
  "schemaVersion": 1,
  "taskId": "dashboard-freeze-review",
  "title": "Dashboard Freeze Review",
  "goal": "Verify Dashboard V2 remains aligned with the approved constitution.",
  "mode": "review",
  "scope": [
    {
      "path": "components/product/DashboardV1.tsx",
      "allowedChanges": ["objective blocker fixes only"]
    }
  ],
  "constraints": [
    "Do not change hierarchy",
    "Do not change data fetching",
    "Respect Dashboard Freeze Rule"
  ],
  "forbiddenChanges": [
    "API changes",
    "router changes",
    "scoring changes",
    "subjective redesign"
  ],
  "requiredReading": [
    "AGENTS.md",
    "docs/project/dashboard-v2-state.md",
    "docs/project/dashboard-design-system.md"
  ],
  "validation": [
    {
      "command": "npx.cmd tsc --noEmit --pretty false --incremental false",
      "required": true
    },
    {
      "command": "npm run audit:dashboard-integration",
      "required": true
    }
  ],
  "expected_output": [
    "files changed",
    "review decision",
    "validation results"
  ],
  "acceptanceCriteria": [
    "No frozen section redesign",
    "Validation passes"
  ],
  "reviewCriteria": [
    "Constitution review",
    "Runtime review"
  ],
  "screenshotTargets": [],
  "approvalRequired": false
}
```

## Schema Evolution Rules

- Additive fields are allowed in future versions.
- Removing or renaming fields requires a new schema version.
- Downstream agents must reject unknown required modes.
- Missing required validation must block acceptance unless explicitly waived by a human reviewer.
